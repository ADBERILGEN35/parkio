# Brand Checklist

Use this before publishing any Parkio asset.

## Positioning

- [ ] Uses the canonical description.
- [ ] Explains Parkio within 30 seconds.
- [ ] Says who it is for.
- [ ] Says what problem it solves.
- [ ] Says the current stage honestly.

## Claims

- [ ] Does not claim live beta unless deployment evidence exists.
- [ ] Does not claim public production readiness.
- [ ] Does not claim users, revenue, partnerships, patents, funding, or startup-program acceptance.
- [ ] Uses TBD or Not yet measured for unknown metrics.
- [ ] Does not guarantee parking availability.

## Visuals

- [ ] Feels modern, calm, reliable, friendly, and professional.
- [ ] Avoids crypto, gaming, dark hacker, taxi, and generic map clone aesthetics.
- [ ] Uses Parkio Teal as the main brand color.
- [ ] Uses status colors with labels/icons, not color alone.
- [ ] Maintains accessible contrast.

## Copy

- [ ] Uses plain language.
- [ ] Avoids corporate buzzwords.
- [ ] Avoids hype.
- [ ] Explains privacy-sensitive behavior clearly.
- [ ] Distinguishes application readiness from live hosted beta.

## UI and Marketing

- [ ] CTAs are clear and action-oriented.
- [ ] Landing page has a visible beta status note.
- [ ] Screenshots use demo data only.
- [ ] Photography avoids readable plates and private details.
- [ ] Technical credibility is translated into user/reviewer value.

## Final Gate

If a claim would make a beta tester, investor, or cloud reviewer assume Parkio is already live, scaled, or revenue-generating, rewrite it.
