# UI Principles

## Product UI Goals

Parkio UI should help users act quickly without feeling rushed. The interface should feel calm, trustworthy, and precise.

## Principles

### Clarity First

Every screen should answer what the user can do next: find, share, verify, claim, report, or review.

### Real Data Over Decoration

Prioritize spot freshness, verification state, distance, legal context, vehicle fit, and trust signals.

### Trust Is Visible

Show why a spot is credible: photo, time, status, verification, contributor trust, and report state.

### Privacy Is Understandable

Explain location and Smart Return choices in plain language. Do not hide privacy-sensitive behavior behind generic settings.

### Calm Density

Information can be dense, but it should not feel crowded. Use hierarchy, spacing, and progressive disclosure.

### Mobile First

Capture and parking decisions happen on mobile. Keep primary actions thumb-accessible and flows short.

## Interaction Principles

- Primary actions should be obvious.
- Risky actions require clear confirmation.
- Loading states should use skeletons where content shape is known.
- Empty states should tell users how to create value.
- Errors should include what happened and what to do next.
- Status should not rely on color alone.

## Accessibility

- Body text at least 16 px.
- High-contrast text.
- Visible focus states.
- Large touch targets.
- Labels for icons.
- Respect reduced motion.

## Product Screens To Prioritize

- Map/discovery.
- Spot detail.
- Share a spot.
- Verification/claim.
- Reports.
- Notifications.
- Smart Return.
- Trust/impact.
- Moderation.
