# Component Personality

## Overall Feel

Components should feel precise, friendly, and dependable. Avoid over-rounded playful UI and heavy enterprise panels.

## Buttons

- Primary: Parkio Teal background, white text.
- Secondary: white or transparent surface with Parkio Teal/Ink text.
- Tertiary: text-only or icon+label for low-emphasis actions.
- Destructive: Report Red with explicit label.

Button labels should be action-oriented:

- "Join beta waitlist."
- "Share a spot."
- "Verify spot."
- "Report issue."
- "View documentation."

## Cards

Use cards for discrete items:

- Spot result.
- Feature item.
- FAQ group.
- Beta step.
- Technical evidence item.

Avoid cards inside cards.

## Forms

- Labels above fields.
- Helper text for privacy-sensitive fields.
- Consent text should be explicit and readable.
- Errors should appear next to the field and in a summary where useful.

## Badges

Badges should communicate status:

- Verified.
- Claimed.
- Reported.
- Restricted.
- Beta.
- Not live.

Badges should be compact, readable, and paired with icons only when useful.

## Navigation

Landing page navigation should be simple:

- Product.
- Trust.
- Technology.
- Beta.
- FAQ.
- Contact.

Avoid overloaded menus before public launch.

## Product Screenshot Frames

Use simple device/browser frames. Do not use heavy shadows, tilted mockups, or decorative stacks that hide the actual product.
