# Landing Page Wireframe

This wireframe defines the first public-facing `parkio.dev` page. It is designed for implementation in Sprint S2 without making additional product strategy decisions.

## Page Objective

Help visitors quickly understand what Parkio is, why it matters, whether it is ready for them, and what action they should take next.

Primary conversion: join the beta waitlist.

Secondary conversions:

- Follow development.
- Contact the founder.
- View technical documentation.

## Desktop Structure

1. Header
2. Hero
3. Problem
4. How Parkio Works
5. Features
6. Trust and Privacy
7. Technology Credibility
8. Hosted Beta
9. FAQ
10. Footer

The hero should leave a visible hint of the next section on common desktop viewport heights. Avoid a full-screen hero that hides the page structure.

## Mobile Structure

1. Compact header with logo and primary CTA
2. Hero copy
3. Product workflow preview
4. Problem
5. How Parkio Works
6. Features
7. Trust and Privacy
8. Technology Credibility
9. Hosted Beta
10. FAQ
11. Footer

Mobile should prioritize reading flow over symmetry. Product preview content can stack below the hero copy.

## Header

Elements:

- Parkio wordmark or logo placeholder
- Navigation links: Product, Trust, Technology, Beta, FAQ
- Primary CTA: Join beta waitlist

Behavior:

- Header should feel lightweight and utility-focused.
- On mobile, collapse navigation into a menu while keeping the primary CTA visible if space allows.
- Do not use a heavy enterprise-style nav bar.

## Hero

Hero headline:

> Parking intelligence powered by real drivers.

Hero subheadline:

> Parkio helps drivers find, share, verify, and manage real-world parking availability through a community-powered, privacy-conscious platform.

Status line:

> Currently in release-candidate and hosted-beta preparation. Public production is not live yet.

Primary CTA:

- Join beta waitlist

Secondary CTAs:

- View technical documentation
- Follow development

Visual:

- Use a product workflow preview rather than a decorative illustration.
- Show the sequence: find a spot, share a spot, verify availability, manage return.
- Keep map references abstract enough that Parkio does not look like a Google Maps or Apple Maps clone.

## Problem Section

Layout:

- One direct statement of the parking uncertainty problem.
- Three supporting points: uncertainty, stale information, inefficient sharing.

The section should be scannable and not statistics-heavy unless sourced data is later added.

## How Parkio Works

Use four steps:

1. Find
2. Share
3. Verify
4. Return

Each step should include a short phrase, a simple icon direction, and one user benefit.

## Features

Recommended feature groups:

- Real-world spot sharing
- Community verification
- Claims and reports
- Smart Return
- Notifications
- Trust and moderation
- Mobile-first surfaces
- Web access for beta and review workflows

Use concise cards or rows. Avoid nested cards.

## Trust and Privacy

This section should appear before deep technical content because it answers a visitor's first risk question.

Content blocks:

- Privacy-conscious by design
- Community trust signals
- Moderation and reports
- Honest beta-stage limitations

## Technology Credibility

Purpose:

- Translate engineering maturity into product trust.
- Avoid dense architecture diagrams on the landing page.

Content:

- Hosted-beta preparation
- Backend and frontend certification references
- Modern service architecture
- Observability and operational planning
- Link to technical documentation

## Hosted Beta

Purpose:

- Make current availability explicit.
- Invite the right early testers.

Content:

- What is ready
- What is not public-production ready
- Who should join
- What beta testers can expect
- Primary CTA repeated

## FAQ

Use 8 to 10 high-intent questions. Keep answers short and link to the full startup FAQ or technical docs where needed.

## Footer

Elements:

- Parkio name and one-line description
- `parkio.dev`
- Links: Documentation, GitHub repo placeholder, Contact founder, Privacy placeholder
- Stage note: release-candidate / hosted-beta preparation

Do not include social proof, customer logos, press quotes, or partner logos unless they become real and documented.
