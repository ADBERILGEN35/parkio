# Landing Page Sections

This document defines section-level content for the first `parkio.dev` landing page.

## 1. Hero

Objective: establish what Parkio is and prompt the right next action.

Headline:

> Parking intelligence powered by real drivers.

Subheadline:

> Parkio helps drivers find, share, verify, and manage real-world parking availability through a community-powered, privacy-conscious platform.

Status copy:

> Parkio is currently in release-candidate and hosted-beta preparation. The public production service is not live yet.

Primary CTA:

- Join beta waitlist

Secondary CTAs:

- View technical documentation
- Follow development

Visual direction:

- Product workflow preview
- Mobile-first screen sequence
- Abstract parking bay, route, verification, and return indicators

## 2. Problem

Objective: make the pain clear without unsupported market statistics.

Section headline:

> Parking should not depend on stale guesses.

Supporting copy:

> Drivers often make parking decisions with incomplete, outdated, or scattered information. Real availability changes quickly, and the people closest to the curb usually have the freshest signal.

Key points:

- Availability is uncertain.
- Useful information is fragmented.
- Existing navigation and map tools do not fully solve real-time curbside availability.

## 3. Solution

Objective: show the basic product loop.

Section headline:

> A shared signal for real-world parking.

Content:

- Drivers share available spots.
- Other drivers verify, claim, or report changes.
- Trust signals help the community judge freshness.
- Smart Return and notifications help drivers manage parking after arrival.

CTA:

- See how Parkio works

## 4. How It Works

Objective: make the workflow easy to remember.

Steps:

1. Find: discover nearby parking signals.
2. Share: upload or report a real-world spot.
3. Verify: confirm whether availability is still useful.
4. Return: use Smart Return and notifications to manage next steps.

Design note:

- Use a horizontal timeline on desktop.
- Use a vertical stepper on mobile.

## 5. Features

Objective: communicate product scope without overloading the page.

Feature groups:

- Spot sharing: contribute real availability signals.
- Verification: keep community information fresh.
- Claiming and reports: reduce ambiguity around spot status.
- Smart Return: help drivers return to parking context.
- Notifications: support timely parking updates.
- Trust and moderation: keep the beta useful and responsible.

Avoid:

- Long feature checklists.
- Claims that features are public-production proven.
- Unsupported automation or AI claims.

## 6. Trust and Privacy

Objective: address safety, location, and data concerns before conversion.

Section headline:

> Built for trust, not surveillance.

Content:

- Parkio is privacy-conscious and community-powered.
- The product should make location-related decisions easier without turning user movement into marketing inventory.
- Beta copy must clearly explain what data is collected, what remains TBD, and how user feedback will shape the product.

CTA:

- Read the FAQ

## 7. Technology Credibility

Objective: show that the project is technically serious without becoming a technical landing page.

Section headline:

> Engineered for hosted-beta readiness.

Content:

- Parkio has release-candidate documentation and certification evidence in the repository.
- The architecture supports mobile-first and web surfaces.
- Operational planning covers hosted-beta infrastructure, observability, and public-production blockers.

CTA:

- View technical documentation

## 8. Hosted Beta

Objective: set expectations and collect the right early interest.

Section headline:

> Preparing for a focused hosted beta.

Content:

- Parkio is preparing for hosted beta, not a broad public launch.
- Early testers should be comfortable using a release-candidate product and giving feedback.
- Supported cities, timelines, and invite volume are TBD.

Primary CTA:

- Join beta waitlist

Secondary CTA:

- Contact founder

## 9. FAQ

Objective: reduce uncertainty at the decision point.

Prioritize questions about:

- What Parkio is
- Whether it is live
- Supported cities
- Verification
- Location tracking
- Cost
- Data storage
- Data deletion
- Public-production readiness

## 10. Footer

Objective: provide orientation and diligence links.

Content:

- Parkio one-line description
- `parkio.dev`
- Documentation link
- GitHub repo placeholder
- Contact founder
- Privacy placeholder
- Release-candidate / hosted-beta preparation status
