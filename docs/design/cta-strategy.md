# CTA Strategy

The landing page should guide visitors toward one primary action while preserving useful secondary paths for reviewers, investors, and technical audiences.

## CTA Hierarchy

Primary CTA:

- Join beta waitlist

Secondary CTAs:

- View technical documentation
- Follow development
- Contact founder

Tertiary links:

- Read FAQ
- Learn how it works
- View startup package

## Primary CTA Use

Label:

> Join beta waitlist

Use in:

- Header
- Hero
- Hosted Beta section
- Final pre-footer CTA

Behavior:

- Opens or scrolls to the waitlist form.
- Does not imply instant access.
- Does not say "Start parking now" or "Use Parkio today."

Supporting microcopy:

> Join the waitlist for future hosted-beta invites. Availability, supported areas, and timing are TBD.

## Secondary CTA Use

### View Technical Documentation

Audience:

- Startup-program reviewers
- Technical due diligence reviewers
- Investors who want proof of seriousness

Destination:

- Repository documentation or public documentation page when available.

Microcopy:

> Review release-candidate documentation, certification evidence, and hosted-beta planning.

### Follow Development

Audience:

- Curious visitors
- Early supporters
- Open-source or GitHub-oriented reviewers

Destination:

- GitHub repo or development updates page. URL is TBD unless already public.

Microcopy:

> Follow Parkio as it moves from release candidate to hosted beta.

### Contact Founder

Audience:

- Investors
- Startup programs
- Potential beta partners
- Press or community organizers

Destination:

- Contact method TBD.

Microcopy:

> For startup-program, investor, or beta collaboration inquiries.

## CTA Placement

Header:

- One primary CTA only.

Hero:

- Primary CTA plus one secondary CTA.
- Prefer "View technical documentation" as the visible secondary CTA.

Mid-page:

- Use text links sparingly after problem, solution, and trust sections.

Hosted Beta:

- Repeat primary CTA.
- Add "Contact founder" as secondary for serious inquiries.

Footer:

- Include all secondary links in low-emphasis form.

## CTA States

Recommended states:

- Default
- Hover
- Focus
- Loading
- Submitted
- Error
- Disabled when required consent is missing

Accessibility:

- Buttons must have visible focus states.
- CTA labels must describe the action.
- Do not rely on color alone for disabled or error states.

## Measurement Intent

If analytics are later implemented, measure:

- Hero primary CTA click
- Header primary CTA click
- Hosted beta CTA click
- Waitlist form start
- Waitlist form submit
- Documentation link click
- Contact founder click

Do not implement tracking before privacy and consent decisions are documented.
